## 一、交互链路：统一为 Begin / Cancel / End

**问题**：`EndInteract` 被语义相反的调用方共用；自动交互取消时不通知服务端，导致走出撤离区后服务端 GA 继续跑满时长并弹结算。

| 动词 | 发起方 | 本地行为 | 通知服务端 |
|---|---|---|---|
| Begin | 按键 / 体积进入 | 开场读条、藏提示、Tracker 开始 | `ServerBeginInteract` |
| Cancel | 再按一次 / 体积离开 | 关读条、清 Tracker、恢复提示 | `ServerCancelInteract` |
| End | 服务端 GA 结束（RPC 回来） | 同上，但**不发任何 RPC** | 无 |

- `ADZ_PlayerController` 公开面只剩 `BeginInteract` / `CancelInteract` / `EndInteract`；`Interact`、`InteractHighlightActor` 转私有，且"进行中 → 取消"的判断提前到取高亮目标之前（目标中途不再高亮也能取消）。
- `FDZ_InteractTracker::End()` → `Reset()`，避免和 Controller 的 End 混淆。
- `ADZ_InteractableActor::NotifyAutoInteractCancel` 改调 `CancelInteract()`。

## 三、能力基类：`UDZ_GameplayAbility` + `EDZAbilityEndReason`

- `bWasCancelled` 按引擎惯例只表示"这次不是正常结束"（失败也传 true）。
- 具体原因走 `SetEndReason(Reason, Detail)`：`Completed`（默认）/ `Cancelled` / `Failed` + `FString Detail`（只进日志）。
- `EndAbility` 统一解析（显式 `Failed`/`Cancelled` 压过 `bWasCancelled`，其余按 `bWasCancelled` 推断）、打一条 `[Ability] ... End. Reason=... Detail=...` 日志、调 `OnAbilityEnded(Reason)`。
- `PreActivate` 里复位，避免 InstancedPerActor 复用实例时串味。
- `DZ_AttackAbility` 改为继承 `UDZ_GameplayAbility`。

## 四、结算落地

链路：

```
BP_ExtactionZone::OnInteractCompleted(bSucceeded)
  → SwitchHasAuthority → NotifyExtractionSucceed
  → if bSucceeded → NotifyGameEnd(true)

ADZ_PlayerCharacter::Death()（服务端）
  → NotifyGameEnd(false)

NotifyGameEnd(bExtracted)
  → Settle(Extracted / Dead)
       ├─ HasAuthority / PlayerState / 「一局只结算一次」三重守卫
       ├─ PlayerState->SetExtractResult(...)
       └─ ClientOpenSettlementPanel(BuildSettlementInfo())
            ├─ PlayerState → 成败、击杀数
            ├─ GameState   → 用时
            └─ GetPawn()   → 背包物品（GetAllItems）+ 总价值
  → 客户端：SetSettlementInfo + Open()
```

- 新增 `EDZExtractResult`（`InProgress` / `Extracted` / `Dead`），存 `ADZ_PlayerState`，`Replicated`。
- 结算数据在**服务端**拼成 `FDZ_SettlementInfo` 快照再发 RPC；客户端不读状态，避免复制时序问题。
- 死亡路径顺序：先 `NotifyGameEnd(false)`（背包还满，能列出"丢失的物品"），再 `SetContents` 到容器，最后 `ClearAll`。
